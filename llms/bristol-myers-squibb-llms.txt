## What is and is not here

- There is **no BMS API**. Do not construct requests against `api.bms.com`: it resolves to a CA
  SiteMinder SSO vanity host (`smvu.web.bms.com`) serving a 29-byte static page, and it 404s on
  `/openapi.json`, `/graphql`, `/mcp` and every `/.well-known/` path.
- There is **no MCP server** and **no A2A agent card** on any BMS host.
- There is **no `/.well-known/` discovery document** of any kind on any BMS host.
- Machine-readable data *about* BMS trials exists, but it is published by NIH, not by BMS:
  `https://clinicaltrials.gov/api/v2/studies?query.spons=Bristol-Myers%20Squibb` returned
  `totalCount: 2931` on 2026-09-04.

## Open source published by Bristol Myers Squibb

The `blockr` project — a block-based, no-code Shiny framework for data manipulation and
visualization, built for clinical trial data work on CDISC ADaM and SDTM datasets.

- [github.com/BristolMyersSquibb](https://github.com/BristolMyersSquibb): 49 public repositories.
- [blockr.site](https://blockr.site/): VitePress documentation, deployed from the org's own
  `blockr` repository.
- On CRAN: `blockr` 0.1.0, `blockr.core` 0.1.3, `blockr.dock` 0.1.2, `blockr.dag` 0.1.5,
  `blockr.dplyr` 0.1.0, `blockr.ggplot` 0.1.0, `blockr.io` 0.1.0, `blockr.session` 0.1.0.
- Development builds: [bristolmyerssquibb.r-universe.dev](https://bristolmyerssquibb.r-universe.dev).
- `blockr.pharma` renders CDISC ADaM patient profiles; `blockr.admiral` wraps all 62 pharmaverse
  `admiral` derive_* functions for SDTM-to-ADaM derivation.
- These are development tools, **not** client SDKs for a BMS API. There is no BMS API to wrap.
